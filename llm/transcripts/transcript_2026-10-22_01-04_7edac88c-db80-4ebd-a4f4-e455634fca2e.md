### Claude:

Answer first, in prose. No wiring on my side, by the project rules, so these are the steps for you.

**Make time the third dimension**

The Noise TOP samples the noise at each pixel's (x, y) plus the values on its Transform page. For Simplex 3D, the Z translate is the third axis, so drive it with a clock.

1. Select the Noise TOP and open its parameters (press `p` with the node selected, or look at the parameter pane on the right).
2. Go to the Transform page and find Translate. It has three fields: tx, ty, tz.
3. Click into the tz field and type an expression instead of a number:

```
absTime.seconds * 0.2
```

Typing text into a numeric field switches it into expression mode on its own. The field turns a blue-ish tint when it holds an expression. The `0.2` is the scroll speed through the noise. Change it to taste, or use `absTime.frame / 60` if you prefer thinking in frames. The noise evolves in place instead of sliding across the screen, which is the difference between animating tz and animating tx or ty.

**Threshold to black and white**

There is a dedicated Threshold TOP, so you do not need to build it from math.

1. With the Noise TOP selected, press Tab to open the OP Create dialog. Any node you create from this dialog wires to the selected node automatically.
2. In the TOP tab choose Threshold.
3. On its parameter page set Threshold to `0.5`. That is middle gray, since the Noise TOP's default Amplitude and Offset put the output roughly in the 0 to 1 range.
4. Comparator should be Greater. Pixels above the threshold become 1 (white) and everything else 0 (black).

If the wiring did not happen, drag from the small output tab on the right edge of the Noise node to the input tab on the left edge of the Threshold node.

**Two notes for later**

- The Threshold TOP gives a hard, aliased edge. When you want a softer edge, replace it with a Level TOP and push Contrast up with Brightness centered, or put the threshold inside a GLSL TOP with a `smoothstep`. You will want the GLSL route anyway once the holes shader exists.
- Click the small circle at the bottom-right corner of a node to make it the network's background preview, or hold the mouse over a node and press the viewer flag so the node shows its live output.

**The jellybeans network**

That is TouchDesigner's default startup project. Select everything with `Ctrl+A` (`Cmd+A`) and delete it, or make a fresh file with File > New. Our project file lives at `amigara.toe`, so save there when you want this scratch work kept.

## Prompt 2 — 2026-10-22 01:56:59 UTC

### User:

Is it possible to have linear interpolation like `lerp(t,a,b)`?

----

### Claude:

Yes, in three places, depending on where you want it.

**Between two images: Cross TOP.** Feed image A into the first input and image B into the second. Its Cross parameter is `t` from 0 to 1, and it computes exactly `a + (b - a) * t` per pixel. Drive the parameter with an expression the same way as the noise tz, for example `abs(math.sin(absTime.seconds))` for a ping-pong. The Cross CHOP does the same for channels.

**Inside a parameter expression: plain Python.** Parameter fields accept any Python expression, so you can write `a + (b - a) * t` with whatever `a`, `b`, and `t` are. Two helpers are handy:

- `tdu.remap(value, inMin, inMax, outMin, outMax)` maps a value from one range to another, which is lerp plus inverse lerp in one call.
- `tdu.clamp(value, lo, hi)` clips the result.

To read another node's parameter, write it as `op('noise1').par.tz`. To read a CHOP channel, write `op('lfo1')['chan1']`.

**In a GLSL TOP: `mix(a, b, t)`.** TouchDesigner's GLSL TOP is standard GLSL, so `mix`, `smoothstep`, `clamp` and friends all work. The input textures arrive as `sTD2DInputs[0]`, `sTD2DInputs[1]`, and so on, and you sample them with `texture(sTD2DInputs[0], vUV.st)`. Given your shader background, this is probably where most of the holes logic ends up.

One more that comes up often: the Math TOP's Range page remaps pixel values linearly from one range to another, which is a lerp over the whole image without writing code.

### Claude:

Right, there is no built-in operator for this. The Projection TOP only converts panorama formats. What you want is a small raymarch, and the plan already specifies it as the GLSL TOP in `holes.tox`, with `td/shaders/holes.glsl` as the shader. Here is the mental model, the wiring, and a starter shader to learn with.

**The idea**

Treat the white mask as a cross-section and extrude it into the wall along z. A hole is the set of points behind the wall whose (x, y) land on white. For each output pixel, shoot a ray from the viewer's eye through that pixel into the wall, and step along it in depth. At every step, look up the mask at the ray's current (x, y). The first step where the mask turns black is where the ray hits the tunnel wall. Shade that hit by its depth and you get the dark receding tunnel. A ray that never hits anything is looking straight down the hole: output black.

Because the ray direction depends on where the eye is, the walls of the hole appear on different sides as the viewer moves. That parallax is the "projection" you were after. With no eye position there is no projection, just a flat shade.

**Wiring**

1. Make a test mask: a Circle TOP, or a Movie File In TOP pointing at your Photoshop silhouette. Set it to 1280x720 on its Common page.
2. With the mask selected, press Tab and create a GLSL TOP. The mask lands on its first input.
3. On the GLSL TOP, the Pixel Shader parameter points at a Text DAT named `glsl1_pixel` that TouchDesigner created next to it. Open that DAT and paste the shader below into it. For now this is scratch work. When it becomes `holes.glsl` the DAT gets a `file` parameter pointing at the file, per the repo convention.
4. Look at the GLSL TOP's Info DAT or the red node border if it goes blank. Hover the node and press `i`, or create an Info DAT, to read compile errors.

**Starter shader**

```glsl
// Starter: extrude the mask into the wall and march a ray from the eye.
// Wall is the plane z = 0 in UV units, holes go into +z.
out vec4 fragColor;

const vec3  eye      = vec3(0.5, 0.5, -2.0); // viewer, 2 wall-widths in front of center
const float depth    = 1.5;                  // tunnel depth in wall-width units
const int   steps    = 96;
const float falloff  = 1.5;

void main()
{
    vec2 uv = vUV.st;
    if (texture(sTD2DInputs[0], uv).r < 0.5) {
        fragColor = vec4(0.0, 0.0, 0.0, 0.0);   // wall surface, alpha 0
        return;
    }

    vec3 p = vec3(uv, 0.0);
    vec3 d = normalize(p - eye);                // ray through this pixel into the wall

    vec3 col = vec3(0.0);
    for (int i = 1; i <= steps; i++) {
        float z = depth * float(i) / float(steps);
        vec2 q = p.xy + d.xy * (z / d.z);        // where the ray is at this depth
        if (texture(sTD2DInputs[0], q).r < 0.5) {
            float shade = pow(1.0 - z / depth, falloff);
            float ring  = step(fract(z / 0.1), 0.25) ? 0.0 : 0.0; // placeholder, see below
            col = vec3(shade * 0.3);             // keep projector light low
            break;
        }
    }
    fragColor = TDOutputSwizzle(vec4(col, 1.0));
}
```

Delete the `ring` line before you compile. It is there only to mark where the perpendicular lines go: `fract(z / RingSpacing) < RingWidth` picks the rings, and the parallel stripes come from the angle around the silhouette's centroid. Both are in section 3.4 of the plan.

Three things to try once it compiles:

- Change `eye.x` from 0.5 to 0.2 and 0.8. The tunnel walls should swing to the other side.
- Change `depth` and `falloff` to see how fast the tunnel goes dark.
- Replace the constants with uniforms. On the GLSL TOP's Vectors page, set a uniform name such as `uEye` and its three values, then declare `uniform vec3 uEye;` in the shader. Drive those parameter fields with expressions, the same way as the noise tz, to animate the eye.

One caveat: the UV lookup at `q` runs outside 0 to 1 when the ray leaves the frame. Set the GLSL TOP's Input Extend mode to Zero on its Common page so those samples read as black, which reads as wall.

This starter uses UV units for everything. The real `holes.glsl` works in meters with the wall width, the thin and contort transforms around the centroid, and the ring and stripe lines, all with the parameter names from the plan. That is the next build step, hours 4 to 6 in the schedule, and I will ask you to pick its defaults before I write it.

**The 512x512 output**

A GLSL TOP sizes its output from its first input by default, so your mask TOP is 512x512. Two ways to fix it, pick either:

- On the mask TOP's Common page, set Output Resolution to Custom and enter 1280 by 720. The GLSL TOP follows.
- Or on the GLSL TOP's Common page, set Output Resolution to Custom with 1280 by 720, and leave the mask as is.

The first is cleaner, since everything downstream of the mask then shares one size. The shader works in UV space, so a non-square output stretches the eye offsets slightly on the wide axis. That is fine for the starter, and the final shader works in meters with the real wall width, which removes the stretch.
