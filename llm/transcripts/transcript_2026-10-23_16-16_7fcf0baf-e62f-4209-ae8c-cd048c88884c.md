### Claude:

**Short answer: partly.** The camera-and-markers half of an XR viewer can be a web page in Safari. The NDI half cannot, because no browser can receive NDI. Details below, then a recommendation for your deadline.

**What works on iPhone Safari**

- No WebXR. iOS Safari exposes WebXR only on visionOS. On iPhone you get a plain page: getUserMedia camera into a canvas, a JavaScript ArUco detector such as js-aruco2 (it has the 4x4 dictionaries), and WebGL drawing the tunnel over the camera frame. That is enough for this project because the four markers already define the wall plane.
- Camera access needs a secure context. A page at http://your-mac.local is refused. You need HTTPS with a self-signed certificate the phone trusts, or a tunnel like Tailscale or ngrok. This is the usual half-hour trap.

**What does not work**

- NDI in a browser. Keep the NDI Out TOP for the assignment and view it with a free NDI monitor app on the phone. That shows the stream, not AR.
- To get the mask into a web page you need a second transport. TouchDesigner's WebRTC path exists, but the signaling setup takes hours. The quick route is a Web Server DAT with a callback that returns the mask as a JPEG from the TOP's saveByteArray method, and the page fetches it about ten times a second. Fine on LAN, and the same server can host the page over HTTPS with the Secure parameter.

**Recommendation for the deadline**

1. Shader stripes first. Parallel lines along the depth axis all converge on the vanishing point, which is the eye's x and y projected onto the wall. So inside the hit branch add a stripe term from the angle around uEye.xy and OR it with the ring:
   ```glsl
   float angle  = atan(q.y - uEye.y, q.x - uEye.x);
   float stripe = step(fract(angle * uParallelCount / 6.2831853), uStripeWidth);
   float line   = max(ring, stripe);
   ```
   with two new Vectors-page uniforms, uParallelCount (48) and uStripeWidth (0.3), matching the plan's names.
2. NDI Out TOP in output.tox, checked with a monitor app on the phone.
3. Only if more than about three hours remain, the web viewer: Web Server DAT serving the page plus JPEG frames, js-aruco2 for the markers. Otherwise show the viewer as TouchDesigner's own Holes mode on the projector and state in the writeup that the phone app is future work.

### Claude:

I wrote [holes.glsl](td/shaders/holes.glsl). The starter stays as it was. Here is how to wire it.

**Repoint the GLSL TOP**

1. Select your existing GLSL TOP and open its parameters.
2. On the GLSL page, find the Pixel Shader parameter. It names the Text DAT that holds the starter.
3. Create a new Text DAT next to it. Name it `holes_glsl`. On its parameters, set File to `td/shaders/holes.glsl` and pulse Load on Start Up or Reload. The DAT now mirrors the file, so Git tracks the code.
4. Set the GLSL TOP's Pixel Shader parameter to `holes_glsl`.
5. Keep Input Extend at Zero on the Common page.

**Add the three new uniforms on the Vectors page**

Each row has a Name, a Value field, and a type. Add these after your existing six:

| Name | Value |
|---|---|
| uParallelCount | 24 |
| uStripeWidth | 0.2 |
| uStripeLevel | 0.5 |

If the Vectors page is out of rows, raise the Number of Vectors count at the top of the page first.

**What you should see**

- With a Circle TOP as the mask, the tunnel shows rings as before plus straight lines running from the rim toward the far end. They all point at one spot, where uEye.x and uEye.y land on the wall.
- Move uEye.x left and right. The stripes swing with the vanishing point while the rings stay flat. That swing is the perspective cue.
- Stripes are half as bright as rings. Raise uStripeLevel toward 1 if the projector loses them.
- Raise uParallelCount for denser hatching. Lower uStripeWidth for thinner lines.

**If the GLSL TOP shows a red error**, open its Info DAT or click the warning triangle. The likely cause is a uniform name typed differently from the file. Names are case sensitive.

Report what you see and we go on to the NDI Out TOP.

### Claude:

Build this in TouchDesigner. The README text is in [td/readme/output.txt](td/readme/output.txt).

**1. Make the component**

1. At the top level of `amigara.toe`, add a Base COMP and name it `output`.
2. Enter it. Add two In TOPs. Name them `mask` and `depth`. Each In TOP gets a Label parameter so the inlets read clearly from outside.
3. Add a Text DAT named `README`. Set its File parameter to `td/readme/output.txt` and pulse Reload. Set Sync to File on so Git keeps it.

**2. Normalize the depth**

NDI carries 8-bit color, so depth must be 0 to 1 before packing.

1. Add a Math TOP after `depth`. On the Range page, set From Range to the near and far distances your FreenectTD TOP outputs. If it gives millimeters, use 500 to 4500. If it already gives 0 to 1, skip this TOP.
2. Set To Range to 1 then 0. Larger is closer, the same convention as the webcam fallback.
3. Check it with a viewer: a person walking toward the Kinect gets brighter.

**3. Pack the channels**

1. Add a Reorder TOP. Connect `mask` to input 1 and the Math TOP to input 2.
2. On its Reorder page set the four output channels:

| Output | Source |
|---|---|
| Red | Input 1 Red |
| Green | Input 2 Red |
| Blue | Zero |
| Alpha | Input 1 Red |

3. On the Common page set Output Resolution to Custom, 1280 by 720. If your mask is a different aspect, the Resolution page's Fit menu decides how it scales. Choose Fill so no border appears.

**4. Send it**

1. Add an NDI Out TOP. Connect the Reorder TOP to it.
2. Set Name to `amigara`. Set Active on. If the operator shows a Frame Rate parameter, set it to 30. Leave the format at RGBA so alpha travels.
3. Also add an Out TOP from the Reorder TOP so the component shows the packed image outside.

**5. Check on the iPhone**

1. Put the phone on the same Wi-Fi as the Mac. A guest network or a client isolation setting blocks discovery.
2. Open Sienna NDI Monitor. When macOS or iOS asks for Local Network access, allow it. The source list should show the Mac's name with `amigara` after it.
3. Tap it. You should see a red silhouette with a green depth gradient, within about 100 ms of movement. Red plus green shows as yellow where both are high.
4. No source listed: on the Mac open System Settings, Network, Firewall. If the firewall is on, allow incoming connections for TouchDesigner, or turn the firewall off for the demo. NDI needs UDP 5353 for discovery and TCP from 5960 upward for video.

**6. Save it**

Only after the phone shows the stream: go up one level, right-click `output`, choose Save Component .tox, and save to `td/output.tox`. Then tell me and I draft the commit message with both the shader and the output component.
